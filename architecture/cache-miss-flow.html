Cache-Aside Pattern Technical Specifications & Edge Cases
Pattern Challenge Impact Recommended Production Solution
Cache Stampede (Thundering Herd) High load spikes PostgreSQL when a popular key expires and hundreds of concurrent requests miss Redis simultaneously. Use Mutex / Distributed Locks (e.g. Redlock) or probabilistic early expiration (XFetch algorithm) so only one thread rebuilds the cache.
Cache Invalidation & Drift Stale data is served if updates in PostgreSQL are not purged or synchronized with Redis. Enforce Write-Through or Cache-Eviction on Update: When mutating data (POST/PATCH/DELETE), purge the cache key (DEL task:101).
Redis Outage / Unavailability API crashes if Redis connection failures are unhandled. Implement Fail-Open Graceful Degradation: Wrap Redis calls in a try/catch. On Redis failure, log warning, fallback to PostgreSQL directly, and return 200 OK.
Cache Penetration Attackers request non-existent IDs repeatedly, constantly bypassing Redis and querying PostgreSQL. Cache null/empty results with short TTL (e.g. SET task:99999 "null" EX 30) or configure a Bloom Filter in front of Redis.
