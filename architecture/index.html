Dual-Persistence Strategy & Data Contract Local-First + REST

Shared Task Contract

type Task = {
  id: string;        // crypto.randomUUID()
  title: string;     // 1-200 chars, trimmed
  completed: boolean;// true | false
  createdAt: string; // ISO 8601 (UTC)
  updatedAt: string; // ISO 8601 (UTC)
};

Both the frontend state, LocalStorage serialization, Express JSON responses, and SQLite columns strictly mirror this contract.

Optimistic Rendering Loop

  1. Instant UI Update: State is mutated in memory first; component re-renders immediately.
  2. Post-Paint Save: useTasks uses requestAnimationFrame + setTimeout(0) to persist to LocalStorage without blocking rendering.
  3. Async REST Call: TaskStorage asynchronously calls Express (POST/PATCH/DELETE) and updates local state upon server confirmation.
  4. Multi-Tab Sync: window.addEventListener('storage') synchronizes edits across different browser tabs without race conditions.

Fault Tolerance & Corruption Protection

Damaged Data Recovery

If LocalStorage text is malformed or schema invalid, it is automatically archived to todo-app.tasks.damaged.<timestamp> to prevent data loss, and an error alert is raised.

Quota & Security Shield

Catches QuotaExceededError and SecurityError when storage is full or disabled (private browsing mode), gracefully notifying the user via MessageBar.

SQLite WAL Concurrency

Backend utilizes SQLite in WAL (Write-Ahead Logging) mode, allowing readers to query while writes occur concurrently without table locks.

Backend REST API Reference Port 3001
GET /api/tasks

Returns array of all tasks sorted by createdAt DESC (200 OK).

POST /api/tasks

Payload: { "title": string }. Creates new task with generated UUID (201 Created).

PATCH /api/tasks/:id

Payload: { "title"?: string, "completed"?: boolean }. Updates task and sets updatedAt (200 OK).

DELETE /api/tasks/:id

Deletes task by ID from SQLite database (200 OK or 404 Not Found).
